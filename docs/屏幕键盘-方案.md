# 屏幕键盘：GNOME 50 Wayland 下的最终方案

> 记录日期：2026-10-23
> 结论先写：**唯一可行方案是 GNOME Shell 扩展 + `Clutter.VirtualInputDevice`**，
> 已实测在 QQ 和 Chrome 里都能输入。
> 源码：`scripts/erhai-osk-ext/`（`metadata.json` + `extension.js`）

---

## 一、问题

平板上只有触屏、没有外接键盘，而在 GNOME Wayland 下：

- 点 QQ / Chrome 的输入框，**什么键盘都不弹**
- 用第三方屏幕键盘（Onboard）打字，**字进不去应用**

---

## 二、逐条排查过的路（都失败，但失败原因各不相同，很重要）

| 方案 | 失败原因 | 证据 |
|---|---|---|
| GNOME 自带屏幕键盘 | 只在应用调用 `zwp_text_input_v3` 时弹。Electron/Chromium **默认不实现**该协议 | mutter 日志关于 text-input 完全为空 |
| 给 QQ 加 `--enable-features=TextInputV3` | flag 名不对，二进制里没有这个字符串 | `strings` 查不到 |
| 给 QQ 加 `--enable-features=WaylandTextInputV3` | flag 名**对**（`strings` 能查到，启动也确实变了），但协议仍没真正上报 | mutter 依旧无任何 text-input 日志 |
| 参考 Chromium 官方 | 他们自己承认 `text_input_manager_v3` "still broken in some ways"，所以不默认开 | chromium issue 40113488 |
| 参考 gnome-shell bug | GNOME 要求应用连续调用 `enable+commit` **两次**，新版 Chromium 只调一次 | gnome-shell#8426；"点两次/敲个实体键"可绕过 |
| Onboard（第三方键盘） | 靠 X11 `XInput` 注入按键，**Wayland 禁止客户端互相注入输入**；退回 GTK 后按键进不去任何应用 | 日志 `XInput event source failed to initialize, falling back to GTK` |
| `wtype`（Wayland 虚拟键盘工具） | **mutter 不实现 `zwp_virtual_keyboard_v1`** | `Compositor does not support the virtual keyboard protocol` |
| `gtk4-layer-shell` + `KeyboardMode.NONE` | **mutter 不实现 `wlr-layer-shell`**。那是个 wlroots 生态协议，GNOME 从来不支持 | `LD_PRELOAD` 修好链接顺序后暴露真因：`your Wayland compositor doesn't support Layer Shell` |
| 普通 GTK 窗口做键盘 | xdg-shell 下**无法**做到"接受鼠标点击但不获取键盘焦点"，这是协议限制 | 一点键盘 QQ 输入框光标就消失 |
| 切到 X11 会话 | GDM 的 greeter 是 Wayland 的 GNOME Shell，**独占 `/dev/dri/card0`**，Xorg 起来就被夺走设备 | Xorg 日志：`Server terminated successfully (0)`，之前大量 `device removed` |
| 让 QQ 跑在 Xwayland + `xdotool`/XTEST | 坐标映射与 mutter 合成位置不一致；按键能触发 X11 铃音但进不了输入框 | `getmouselocation` 落在错误窗口；输入框始终为空 + 系统响铃 |
| `ydotool` + `uinput` 直接注入 | **注入本身是成功的**（实测能进 QQ），但键盘窗口会抢焦点，导致按键进到键盘自己 | 注入 `OSKOK123` 确实出现；点键盘后焦点消失 |

### 关键认知

> **所有失败都发生在"窗口"这一层。** Wayland 的输入隔离不允许普通窗口
> 既接受点击、又不抢焦点；也不允许任何外部进程向别的应用注入按键。
> 只有**合成器内部**才有这个权限。

## 三、最终方案

**GNOME Shell 扩展**。它跑在 mutter 进程内部，因此：

### 三层控制入口（v5 起）

| 入口 | 位置 | 作用 |
|---|---|---|
| **PAD-OSK** 应用图标 | 应用抽屉 | 点一下启用、再点一下禁用整个键盘（`gnome-extensions enable/disable`） |
| **屏幕键盘** 快设开关 | 右上角系统菜单 | 键盘启用时，一拨即显示/收起（`QuickToggle`，与收起箭头共享同一状态） |
| **⠿ 拖动** 条上的 `⌄ / ⌃` | 键盘顶部 | 收起成一条细条，随时展开；同时可拖动定位 |

三者共用同一个 `_setVisible()`，状态不会打架。应用图标的实现：
`/usr/local/bin/pad-osk` + `~/.local/share/applications/pad-osk.desktop`。

### 应用图标与系统菜单必须共用一个状态（重要）

两者最初各管一套状态，结果"先按菜单关闭，再点应用图标"要点两下才有效：

| 入口（旧） | 实际改动 |
|---|---|
| 系统菜单开关 | `_setVisible()` —— 只隐藏面板，扩展仍是启用 |
| 应用图标 | `gnome-extensions disable/enable` —— 改的是扩展启停 |

**修法**：以文件 `~/.config/pad-osk/visible`（内容 `1` / `0`）为唯一事实来源。
扩展用 `Gio.FileMonitor` 监听它；图标脚本改写它。扩展自己改变可见性时也会回写，
写入前先比对当前值，因此不会形成回环。

> 这个坑值得记住：**当一个功能有两个控制入口时，它们必须落在同一个状态上，
> 而不是各自实现"看起来差不多"的动作。**

### 为什么是扩展

1. **注入不受限制**：`Clutter.Seat.create_virtual_device(KEYBOARD_DEVICE)` 拿到虚拟键盘设备，
   `notify_keyval(time, keysym, PRESSED/RELEASED)` 直接送入输入管线，
   mutter 把它当**真实硬件键盘**——应用认不认 `text-input-v3` 都无所谓
2. **不抢焦点**：UI 是 shell 的 chrome 图层（`Main.layoutManager.addTopChrome`），
   不是窗口，根本不参与焦点竞争
3. **空白区可穿透**：容器 `reactive: false`，只有按钮是 reactive，点到空白处事件照常到下层窗口

### 安装

**推荐：装 deb 包**（见 `packaging/README.md`）

```bash
sudo apt install ./dist/pad-osk_1.0_arm64.deb
```

装完注销重新登录一次。包会把扩展装到系统级目录
`/usr/share/gnome-shell/extensions/erhai-osk@local/`，
并提供 `/usr/bin/pad-osk` 和应用抽屉里的 `PAD-OSK` 图标。
卸载用 `sudo apt remove pad-osk`（用户配置 `~/.config/pad-osk/` 保留）。

**手工安装**（不装包时）：

```bash
# 目录（已在设备上就位）
~/.local/share/gnome-shell/extensions/erhai-osk@local/
├── metadata.json      # uuid / shell-version ["50"]
└── extension.js

# 注册到启用列表
gsettings set org.gnome.shell enabled-extensions \
  "['ding@rastersoft.com', 'ubuntu-dock@ubuntu.com', 'tiling-assistant@ubuntu.com', 'erhai-osk@local']"
```

⚠️ **必须重新登录**，两种装法都一样。GNOME 只在启动时扫描扩展目录，
`gnome-extensions enable` 对**新增**目录无效（会报“扩展不存在”）。

### 关键 API 速查

```js
const seat = Clutter.get_default_backend().get_default_seat();
const vdev = seat.create_virtual_device(Clutter.InputDeviceType.KEYBOARD_DEVICE);
const t = Clutter.get_current_event_time();
vdev.notify_keyval(t, Clutter.unicode_to_keysym('a'.codePointAt(0)), Clutter.KeyState.PRESSED);
vdev.notify_keyval(t, Clutter.unicode_to_keysym('a'.codePointAt(0)), Clutter.KeyState.RELEASED);
```

特殊键用 X11 keysym：`BackSpace 0xff08`、`Return 0xff0d`、`Tab 0xff09`、
`Escape 0xff1b`、`space 0x20`、方向键 `0xff51–0xff54`。

GNOME 50 的 typelib 路径：`/usr/lib/aarch64-linux-gnu/mutter-18/`
（Clutter 在该版本叫 `Clutter-18`，Python 的 gi 看不到，只有 GJS 能加载）。

## 四、实测结果

- **QQ**：正常输入 ✓
- **Chrome**：正常输入 ✓
- 不再出现"点键盘后输入框光标消失"
- 不再出现 X11 铃音（那是"按键到了但没有焦点输入框"的提示）
- **中文输入可用 ✓（全应用）** —— 见下面第六节，这条推翻了本方案早期的错误结论

### 中文输入为什么能成（重要更正）

早期结论是"中文不可能"，理由：Electron/Chromium 不实现 `zwp_text_input_v3`。
**这个推理错在路径不全**。输入法到应用至少有三条通道：

| 通道 | 谁在用 | 是否需要 text-input-v3 |
|---|---|---|
| `zwp_text_input_v3` | 原生 Wayland 的 GTK/Qt 应用 | 需要 |
| **XIM**（`ibus-x11`） | **跑在 Xwayland 下的 X11 客户端** | 不需要 |
| ibus GTK4/GTK3 模块 | GTK 应用 | 不需要 |

注入的按键是 mutter 层面的**真实键盘事件**，输入法（本机 `ibus` + `libpinyin`）
照样能截获，走 XIM 把候选词送进应用。**Electron 应用跑在 Xwayland 下就能输中文。**

实测：QQ、Chrome 等**全应用都能打中文**。

#### 怎么切中/英

- 键盘上有 **中/英** 键（右下、原右侧 Alt 位置）→ 发 `Super+Space`
- GNOME 的切换快捷键就是 `<Super>space`（`switch-input-source`）
- 候选词操作：数字键选候选、空格/⏎ 上屏、`←→` 翻页、`⌫` 删拼音、`Esc` 取消

> ⚠️ 副作用：因为 `⊞`(Super) 是粘滞修饰键，**点 ⊞ 再点空格也会触发 Super+Space**
> 而误切输入法——那个"先冒出一个 v"的怪现象就是这么来的（v 是拼音的组字前缀）。

#### 教训

> **只在一条机制路径上验证，就断言"不可能"，是错的。**
> 当时查的是"Electron 支不支持 text-input"，而真正走的是 XIM 这条路。
> 判断"某功能不可行"之前，应当把该功能的**所有实现路径**列全再逐条否掉。

## 五、最终状态与已知限制

**状态：已验收（2026-10-23 22:52，用户确认"OK, no BUG!"）**

当前版本 **v12**，md5 `0aada4b2…`，面板实测 1310×487。

### 已知限制

- 尺寸按"老年用户"标准：字母键 64px 宽、字号 24px。逻辑分辨率 1734×1213，
  四周仍有余量
- 没有长按重复（v14 已补：见功能清单与第六节坑 9）；候选项偏小；
  没有随键盘区域的智能避让

  `gdm-greeter` 用户下，读不到 `/home/user` 的扩展），黑屏约 30 秒后自愈

### 尺寸三档（v13，包 1.0.1）

需求：老年用户觉得固定尺寸不够用，想要能调大调小。

实现要点：

| 问题 | 做法 | 原因 |
|---|---|---|
| 尺寸怎么写 | 所有 px 值写成 1.00 基准，乘以档位 `scale`（默认 0.72 / 0.85 / 0.99） | 三档等比缩放，不会各自漂移 |
| 切换时怎么做 | **就地重设每个按钮的 `style`**，绝不重建 | 重建会把正在按下的触摸转给别的按钮（第六节坑 4） |
| 怎么记住每个键 | 建键时把 `{btn, kind, minW, mod}` 存进 `_styledKeys` | 重设样式时不用再遍历控件树 |
| 小数像素 | 一律 `Math.round` | St/CSS 用小数会发虚 |
| 切换后位置 | 记录切换前高度，`idle_add` 里按新高度把 y 回推，**底边不动** | 否则键盘会向上/向下蹦出屏幕 |
| 持久化 | `position.kf` 里同时写 `[position]` 和 `[layout] size=` | 原来的 `_savePosition` 每次新建 KeyFile，只写位置会丢尺寸 |
| 旧配置 | 没有 `[layout]` 组时按 `medium` 处理 | 老用户升级不炸 |
| 读 `[layout]` 组 | **不要**用 `kf.get_groups().includes('layout')` | GJS 把 `gchar**` 出参映射成 `[["position","layout"], 2]` 元组，`includes()` 永远不匹配，覆盖值会被静默忽略。直接用 `try { kf.get_string('layout', key) } catch` 判断即可 |

微调入口（v13 起）：`~/.config/pad-osk/position.kf` 的 `[layout]` 组支持
`scale_small=` / `scale_medium=` / `scale_large=`（0.40–2.00）。每次点尺寸按钮都会重新读一次，
所以调参不需要重新打包、也不需要注销——这是初版三档（0.80/1.28）手感不合适
之后加的，避免每改一个数字就要走一遍「打包→安装→注销」。

注意 `_saveConfig()` 会重写这个文件：它先把旧配置读回来，把三个 `scale_*`
原样抄回去，否则保存位置时会把用户手调的数值抹掉。

实测校准（重要）：最初按设计稿的「面板 1310px」估算缩放，结果三档整体偏大一档
（`scale 0.65` 实测占了屏宽 52%）。后来用三档实测值直接标定（屏宽 1696px）：

| 缩放 | 面板 | 占屏宽 |
|---|---|---|
| 0.72 | 927×349 | 55% |
| 0.85 | 1120×421 | 66% |
| 0.99 | 1295×491 | 76% |

注意斜率并不严格恒定：`Shift`/`Ctrl` 的文字在某些字号下超过键位 `min-width`，
会把整行撑宽，比例漂 1–2%。所以调参必须对着实测值，别用公式外推。

`_reflow()` 会在每次尺寸变化后打一行日志，方便对着屏幕核对：

```
erhai-osk: panel 1137x419 (65% of 1734px, step medium scale 0.82)
```

档位按钮本身是分段控件：当前档填充当前主题的 `accent`，另两档低对比，避免和键位抢视觉。

### 设置面板与配色（v15）

需求：颜色写死在代码里，想换个观感只能改源码重装；而三档尺寸的按钮一直占着拖动条，
拖动条越挤越窄。于是把「大小」和「颜色」一起收进拖动条上的 `⚙`。

| 决策 | 做法 | 原因 |
|---|---|---|
| 面板形态 | **键盘内部的内联 sheet**，`St.BoxLayout` 显隐 | `St.PopupMenu` 要 `pushModal` 抓输入，本项目所有触摸事故都出在「抓输入 + 触摸序列」上（坑 4、坑 9） |
| 配色怎么组织 | 模块级 `THEMES[]`，每套写全 `key/mod/act/on/grip/btn/close/idle/accent/shift/panel/swatch` 角色 | 角色写全，换主题时不会残留上一套的颜色 |
| 当前主题放哪 | 模块级 `let THEME`，样式函数一律读它 | 不必把主题对象传遍每个函数 |
| 换色怎么生效 | 设 `THEME` 后调 `_applyScale()`（同一个函数已经负责把每个 actor 的 `style` 重设一遍） | 复用尺寸那套就地重排，**不重建控件**（坑 4） |
| 面板自己怎么配色 | `panelAlt` 半透明层 + `grip[1]` 文字 | 浅色主题不能沿用深色那层黑纱，否则一片糊 |
| 主题按钮 | 按钮底色 = 自己的色块（等于预览），当前项描边 `accent` | 不靠文字描述配色 |
| 持久化 | `[layout] theme=`，与 `size=` 同级 | `_saveConfig()` 本来就是「读回来再写」，加一个键不会丢旧字段 |
| 非法值 | 名字不在 `THEMES` 里就回落 `graphite` | 手改配置写错不会变透明键盘 |
| 透明怎么算 | **不改任何样式**，直接 `this._box.opacity = Math.round(OPACITY * 255)` | Clutter 把父 actor 的 alpha 应用到全部子节点，键面/文字/拖动条一起淡，天然一致 |
| 为什么不改颜色 | 早期版本把透明度乘进面板 `rgba()` 的 alpha，结果只有底板变透、键面仍是实色，看起来像「透明的框 + 实心的键」 | 整块玻璃的观感只能靠 actor opacity 拿到 |
| 与配色/尺寸互不干扰 | 换主题只重算颜色，换尺寸只重算 px，透明只动 `opacity` | 三套机制各自独立，不用重新推导叠加关系 |
| 下限 | `OPACITY_MIN = 0.5`，`_setOpacity()` 再夹一次 | 低于 50% 字会糊，看不清键 |
| 持久化 | `[layout] opacity=`，与 `size=` `theme=` 同级 | 同一套「读回来再写」，不丢别的字段 |
| 自定义配色怎么推导 | 只收 `panel/key/mod/act/on` 五个背景色，`fgFor()` 按 WCAG 亮度算前景（黑或白） | 让用户填十个前景色不现实，默认值又必然有一半是错的 |
| 推导其余角色 | `grip/btn/close/idle` 用 `shade()` 在面板色/键色上加减 8%–60%，`accent` 用 `on` | 浅色自定义盘不会残留深色预设的拖动条 |
| 背景图怎么画 | `boxStyle()` 追加 `background-image: url("<file uri>"); background-size: cover` | St 支持 CSS 图片背景，不必自己造 `St.TextureCache` + 尺寸计算 |
| 背景图怎么选 | `选图…` 走 XDG portal 的 `org.freedesktop.portal.FileChooser.OpenFile`（先按 `handle_token` 预测 request 路径并订阅 `Response`，再发请求），失败退回 `zenity --file-selection`；`backgrounds/` 里的文件另外列成按钮 | shell chrome 里没有可用的 GTK 对话框，只能用桌面的选择器服务；文件夹列表保留为 portal 不可用时的入口 |
| 配置目录改名 | `~/.config/erhai-osk` → `~/.config/pad-osk`；`_migrateConfig()` 只在新目录**不存在**时拷一次 | 跟包名对齐，又不会覆盖用户在新目录里已有的设置 |
| 选图时谁在上层 | `_yieldForPicker()` 先 `_setVisible(false, false)` 收起键盘，portal 的 `Response` 回来后再 `_restoreAfterPicker()` | chrome 图层永远画在窗口之上，不收起就把文件选择框盖住了；`false` 保证不动状态文件 |
| 选图卡死怎么办 | 180 秒 `GLib.timeout_add` 兜底恢复 | portal 不回 `Response` 时不能让键盘一直消失 |
| 恢复默认的范围 | 尺寸/配色/透明/位置全重置；**背景只关不删**；`[custom]` 不动 | 用户挑过的图是数据，不该被「恢复默认」顺手丢掉；删文件是 `管理…` 的职责 |
| 背景的删与留 | `无` = `background_enabled=0`（保留路径）；`管理…` 里的 `✕` 才 `Gio.File.delete()`；删的正好是当前图时一并清掉配置 | 三个动作三种含义，互不越界 |
| 删图要二次确认 | 第一次点 `✕` 只把按钮换成 `确认删` / `取消`，5 秒无操作自动复位；`返回`、关闭面板同样取消 | 平板上误触概率高，删除文件是不可逆操作，一次点击不该等于删 |
| 圆角怎么统一 | 只存一个 `RADIUS`：键面直接用它，面板 `max(16, R×2)`、拖动条 `max(10, R+2)`、小按钮 `max(8, R)`、设置面板 `max(12, R+4)` | 默认 8 时正好复现原来的 8/16/10/8/12，放大后比例也不会散 |
| 0 圆角为什么不用 `px()` | `px()` 有 `Math.max(1, …)` 下限，0 会变成 1px；圆角改用 `pxSoft()`，0 输出真正的 `0px` | 直角是合法选项，不能被“防消失”兜底改掉 |

四套配色（`[layout] theme=` 可手改）：

| 名称 | `theme=` | 用途 |
|---|---|---|
| 深灰 | `graphite` | 默认；原配色，夜里不刺眼 |
| 浅色 | `light` | 白天弱光环境、投影演示时更清楚 |

| 高对比 | `contrast` | 纯黑底 + 白/黄/青键面，视力不佳时最清楚 |

面板开合与收起的联动：`⌄` 收起成细条、以及 `✕` 隐藏键盘时，设置面板会一起收掉

## 六、踩过的坑（按发现顺序，全部已修）

1. **`addTopChrome(actor, params)` 传了不认识的参数，控件会「半加入」**
   GNOME 50 已移除 `affectsInputRegion`。调用抛 `Unrecognized parameter`
   时，actor **已经加进了 chrome 层**，只是没拿到正确配置。
   结果是一张覆盖全屏、又不受 GNOME 键盘模块管理的图层：
   - 症状一：输入看起来「全死」，但画面照常刷新
   - 症状二：`ui/keyboard.js:1159 maybeHandleEvent` 反复抛
     `Argument descendant may not be null`
   - 症状三：注销时 shell 卡住不退，5 秒后 `SIGTERM` 超时被 systemd `SIGKILL`
   **正确做法：`addTopChrome(actor)` 不传参数。** 默认值（不占 strut、
   不追踪全屏）本来就是我们想要的。

2. **shell 被 `SIGKILL` 后，重启出来的会话可能没有输入设备**
   重点排查命令：
   ```bash
   lsof /dev/input/event*        # 看 gnome-shell 有没有持有
   ls -l /proc/$(pgrep -x gnome-shell)/fd | grep input
   ```
   正常应有 8 个左右 `/dev/input/eventN` + 若干 `dri`。
   没有的话，mutter 照样渲染、时钟照样走，但**任何触摸/按键都进不来**
   ——看起来像「死机」，实际是「没手」。
   **唯一解法是整机重启**（会话重启救不回来）。

3. **折叠按钮不能放在被折叠的容器里**
   第一版把「▼」放进键盘内部那几行，一收起连按钮一起隐藏，
   就永远展不开了。按钮必须放在**始终可见的拖动条**上。

4. **GNOME 50 没有任何免重启的代码重载手段**
   - `org.gnome.Shell.Eval`：被禁用（`unsafe-mode` 这个 gsettings 键
     在这个版本已不存在）
   - `ReloadExtension`：D-Bus 接口里有声明，但调用返回
     `Method is not implemented`
   - `disable` + `enable`：**复用缓存的 ES 模块**，跑的还是旧代码
   → **改一次代码就要注销/重启一次**。所以要么一次改完，要么接受折腾。

5. **Onboard 在 Wayland 下是纯粹的稳定性风险，已卸载**
   每次登录自启，然后 `XInput event source failed to initialize`
   + AT-SPI 上抛 `SystemError`。它做不到注入，只贡献崩溃。

6. **`notify_keyval()` 不套用 shift level**
   直接送 `!` 的 keysym（0x21）打出来是 `1`。同一个物理键上的上档字符，
   必须发**基键 keysym + 真实按下 Shift_L**。大写字母一直正常，正是因为它
   走的就是这条路。同理适用于 `;:` `'"` `[{` `]}` `,<` `.>` `/?` `` `~ ``
   `-_` `=+` 以及数字键。

7. **切换 Caps/Shift 时不要销毁重建按键**
   触摸的按下和抬起之间若把按钮销毁又重建，抬起事件可能落到同位置的**另一个**
   按钮上，触发一次多余的 `clicked`（表现为先冒出一个莫名其妙的字符）。
   正确做法：保留控件引用，只改 `label.text` 和 `style`。

8. **别用 PowerShell 的 `Set-Content` 改这个文件**
   会把 UTF-8 中文/符号重编码成非法字节序列（本次在字节 3866 处坏掉，
   `E2 8C` 后面跟了非法续字节）。要改就用编辑工具或 `write`；
   写完可以用 `iconv -f UTF-8 -t UTF-8 file >/dev/null` 验证。

9. **`St.Button` 的 click gesture 会吞掉触摸的「松开」**（长按连发踩的坑）
   用 `button-press-event` 起定时器、`button-release-event` 停表，结果
   **按下有、松开永远没有**：一次按下会收到 `touch-event(TOUCH_BEGIN)`
   和模拟出来的 `button-press-event` 两条，松开时 gesture 已经接管了这个
   触摸序列，按钮自己的 release / TOUCH_END 一次都不来 → 定时器停不下来，
   按一下 `⌫` 就删到天荒地老。日志形态是连续 `repeat start`、零 `repeat stop`。
   正确做法：
   - **按下就发第一个键**（不依赖松开），轻点因此也变成"按下即出字"
   - **停表靠 `clicked`**（gesture 唯一会发给我们的松开信号）
   - **再加 `global.stage` 的 `captured-event` 兜底**，手指划到按钮外松手也能停
   - 同一个键的重复 press 要**去重**，否则一次按下发两个字符

10. **设置面板不要做成 `St.PopupMenu`**
    弹出菜单要 `pushModal` 抓输入。本项目所有触摸问题（坑 4 的杂字符、坑 9 的
    release 丢失）本质都是"抓输入 + 触摸序列"打架；再引入一个 modal grab，
    面板里的按钮就得面对和键盘按键一样的坑，还要额外处理点外面关闭。
    设置面板做成键盘内部的内联 sheet：显隐一个 `St.BoxLayout`，不抢 grab，
    位置跟着面板一起重排（复用 `_reflow()`）。
    联动注意：收起/隐藏键盘时调用 `_closeSettings(false)`，因为调用方自己还会
    再 `_reflow()` 一次，两次待执行的重排会各按自己的旧高度推一次面板。

11. **Quick Settings 开关会把「扩展自己隐藏」当成用户操作写回状态文件**
    扩展为了调文件选择器、或者给模态对话框让路而隐藏键盘时，会顺手把开关设成
    unchecked；开关的 `notify::checked` 处理器把这当成用户点的，把 `visible` 写成
    `0`。于是隐藏是临时的、状态却是永久的——选完图键盘再也不自己回来，只能手动开，
    而且下次登录还是关的。
    修法：`_setVisible()` 里用 `_syncingToggle` 标记包住 `checked = ...`，
    处理器见到标记直接返回；「选图后恢复」也不再读状态文件，直接恢复。

12. **对新建的 `GLib.KeyFile` 调 `remove_key()` 会抛异常，整个保存直接中断**
    「清空背景」原本写的是 `kf.remove_key('layout', 'background')`。但 `kf` 是
    每次 `_saveConfig()` 新建的空对象，里面根本没有这个键，`remove_key()` 抛
    `KeyFileError: 键文件在组"layout"中没有键"background"` —— 异常跳过了后面的
    `save_to_file()`，于是**那一次保存全军覆没**：位置、尺寸、主题、透明度全都
    没落盘。症状很隐蔽：日志里只有一行 `save config failed`，界面上看起来一切
    正常（内存里的值是对的），重启后才发现全回到旧值。
    修法：**不写就等于删掉**——新 KeyFile 本来就没有这个键，去掉 `remove_key()`
    即可，不要试图“删除”一个不存在的键。
